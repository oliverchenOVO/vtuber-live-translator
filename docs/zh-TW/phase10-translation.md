# Phase 10：翻譯可靠性修復

> 本頁是 [英文原始報告](../../PHASE10_REPORT.md)的繁體中文閱讀版。**TRANSLATION CRITICAL RESOLVED: NO**。這是開發機上的驗證紀錄，不構成 GA、發行 artifact 或版本 tag 的授權。

## 改動

- Final 譯文在寫成正式翻譯前，依序經過確定性事實防護、結構化原文／譯文對齊檢查及獨立的反向翻譯證據檢查。不確定就保持 pending。選用的 7B 修正會收到原文、失敗候選和具體失敗原因；新輸出也須重新過相同檢查。
- Partial 不讀取對話上下文，極短片段先等待，且永不呼叫 7B。真實模型比較發現上下文外溢後，Final 上下文預設關閉，但保留實驗設定。
- 每筆 Segment 保存 ASR 信心值。低信心來源與重複的日文非詞彙填充音標為 `uncertain_source`。`verifying`、`repair_pending`、`pending`、`rejected` 等狀態會持久化；匯出 pending 時顯示原文，不展示失敗候選。
- Glossary prompt 只注入有匹配的來源別名，重疊時優先較長別名。長 Final 按句子邊界切分翻譯，仍保留同一 Segment ID。
- UI 改用人類可讀的翻譯狀態。音訊擷取與 diarization 未改；ASR 只在既有結果加上信心值。
- Pending 掃描改為超過前 64 筆仍可分頁，capture 期間優先較新的 Final。語意驗證失敗在當次執行延後，不反覆塞滿即時佇列；runtime 中斷仍做指數退避。重新選 Session 或改翻譯設定後可再次嘗試。

## 真實模型與品質門檻

先前 Phase 9 的 22 筆明顯不良譯文，用真實本機 Qwen2.5 1.5B 重跑：**2 筆修正、20 筆 pending、0 筆舊錯譯曝光**。選用 Qwen2.5 7B 針對性修正時，22 筆中有 15 筆呼叫 7B，結果仍是 **2 筆修正、20 筆 pending**；7B 對這批沒有新增修正，Balanced 預設也不啟用它。這改善了保守性，**不代表翻譯覆蓋率可用**。

固定 400 筆測試包含 300 日文、100 英文，跨閒聊、未完成句、遊戲、俚語、數字、時間、否定、推測、名字與多子句。資料有參考譯文與語意事實，但很多是同一基礎句的相關變體，**不是 400 個獨立直播 speech turn**。真實模型初次接受日文 **63/300**、英文 **17/100**；加上後續防護後，最後為 **79/400（19.75%）已翻譯、321/400（80.25%）pending**。原先通過的 39 筆重新經過對齊解析與反向檢查仍通過；腳本把失敗候選都視為 pending，不另計 rejected 子集。

通過驗證器**不代表語意正確**。接受的錯例包括：`弾がない` → `沒有彈簧`（物件錯）、`胡桃のあを応援する` → `支援核桃的`（名字遺失）、`水飲んでくる` → `水喝來了`（動作改變）、`回線が重い` → `沉重的線路`（直譯錯）。未完成句 `みんなと一緒に…、ね` → `大家一起來吧。` 是無根據補完，後加防護已將其降為 pending。這些只是**已觀察到的錯誤下限**，不是完整獨立類別稽核。檢視的接受列沒有發現明顯數字／否定錯誤，也**不能**宣稱這兩類已達零錯誤門檻。

對 Phase 9 另外 100 日文、50 英文做原文／譯文文字盲審，Codex（**非獨立真人**）記錄 20 筆已接受譯文：10 正確、7 可接受、3 錯誤；130 筆 pending。三筆錯誤的日文 ASR 來源本身不通順。這既不是原始音訊審查，也未達獨立人工驗收門檻。

## 30 分鐘真實 Chrome 整合測試

2026-09-25 日文單人 Chrome／YouTube 測試使用完整 **Process Loopback → Faster-Whisper → 翻譯 → Sherpa diarization → SQLite**。Session 完成，**193 筆 Final 原文**留在 SQLite；只有 **23/193（11.9%）**有 Final 譯文，另 **170/193（88.1%）**無譯文：53 `uncertain_source`、12 `rejected`、104 `pending`、1 筆在完成逾時時仍 `verifying`。有界翻譯佇列達容量 12；程式 RSS 峰值 **976.9 MiB**，平均 CPU **64.8% 單核心**。重疊的 Ollama 探測視窗約 **1,605.8 MiB RSS 峰值**及 **300.6% 單核心平均 CPU**。Balanced 過程沒有載入 7B。最高平滑翻譯延遲達 **128.8 秒**，不具自然直播體感。這輪長測在重試節流與分頁掃描修正**之前**；修正後有測試，尚無第二輪 30 分鐘長測。

15 次真實模型 Partial 呼叫平均 **0.603 秒**、中位 **0.391 秒**。固定 400 筆 Final 呼叫平均 **10.15 秒**、中位 **11.45 秒**、P95 **18.19 秒**，**不含即時佇列等待**。150 筆審查探測平均每 Final **9.70 秒**；達到驗證階段的對齊／反向證據工作約 **10.0 秒**。實際直播佇列延遲更大，不能把離線平均當 Studio 延遲。

長測仍有錯誤接受，例如 `どう?` → `你好？`、`んんんんん` → `囉嗦`。後來加的規則攔重複填充音、沒有中文字的日文輸出與額外西文倒問號，但這些規則加在長測程序載入程式碼**之後**，只完成單元測試。1.5B 對齊模型可能認可自己的錯譯，反向詞彙探測也無法證明完整語意，因此其他錯誤仍可能存在。

八句日文另比較無上下文、前一句、前三句和前 30 秒上下文；每種模式各有兩句通過。較長上下文會對錯亂 ASR 加入看似合理卻無來源的故事細節；前一句上下文曾把衣服設計誤改為穿衣動作，因此預設改成**無上下文**。真實模型 prompt injection 個案中，英文指令式來源保持 pending，日文來源被當作字面語音翻譯；這只證明所測個案，**不能宣稱普遍免疫**。

ASR 信心是 `exp(mean(avg_logprob))` 的啟發式代理量，**不是正確率校準機率**。截至 2026-10-02，Phase 1–10 測試 **446 項通過**，`compileall` 與 `git diff --check` 也通過；mock 測試涵蓋對齊、數字／否定／推測／實體防護、詞庫、7B 修正、持久化、匯出、佇列上限與恢復。但**真實模型失敗的證據優先於綠色單元測試**。

## 結論與重現

門檻仍為 **NO**：有錯譯通過、翻譯覆蓋率過低、持續直播延遲過高。盲審是助理而非獨立人工。乾淨 Windows、Installer、Overlay 硬體、來源矩陣、GA 與 Phase 11 均不在本階段範圍。

可用 `scripts/phase10_retranslate.py` 重跑固定的 22／400／150 筆；`phase10_context_probe.py`、`phase10_injection_probe.py`、`phase10_latency_probe.py` 做真實模型探測；`phase10_live_soak.py` 執行 Windows 程序音訊整合長測。輸出留在 ignored `data/phase10/`，不寫原始音訊。
