# Phase 10 Translation Reliability Recovery

**TRANSLATION CRITICAL RESOLVED: NO.** This is a development-PC validation record. It does not authorize GA, a release artifact, or a version tag.

## Changes

- Final translations now pass deterministic fact guards, a structured source-to-translation alignment review, and an independent reverse-translation evidence probe before they can be saved as Final. Inconclusive evidence remains pending. The optional 7B path receives the original, failed candidate, and specific failure; its output must pass the same checks again.
- Partial translation ignores conversation context, waits for very short fragments, and never invokes 7B. Final context is disabled by default after a real-model comparison showed context leakage; it remains configurable for later experiments.
- ASR confidence is saved with each segment. Low-confidence source and repeated non-lexical Japanese filler are marked `uncertain_source`. Translation state (`verifying`, `repair_pending`, `pending`, `rejected`) is durable, and pending export shows the original instead of a failed candidate.
- Glossary prompts include only matched source aliases, with longest overlapping match first. Long Final utterances split at sentence boundaries while retaining one segment identity.
- The UI uses human-readable translation states. Audio capture and diarization behavior were left intact; ASR only gained a confidence value on its existing results.
- Pending scans are paged beyond the first 64 rows and prioritize recent Final segments while capturing. A semantic verification failure is deferred for the current run instead of repeatedly filling the live queue; a runtime outage retains exponential retry. Explicit Session reselection or translation-setting changes permit another attempt.

## Evidence and release gate

The prior 22 clearly bad Phase 9 samples were replayed against the real local Qwen 2.5 1.5B model: **2 corrected, 20 pending, 0 old bad candidates exposed**. With optional targeted Qwen 2.5 7B repair enabled, 15/22 invoked 7B and the result was still **2 corrected, 20 pending**. The 7B path added no correction in this sample and is not enabled in the balanced preset. This is a safety improvement, not usable translation coverage.

The 400-row fixed fixture has 300 Japanese and 100 English rows across casual, incomplete, gaming, slang, numbers, time, negation, uncertainty, names, and multi-clause categories. Rows have a reference and semantic facts, but many are related variants of authored base utterances; they are not 400 independent live speech turns. The complete real-model run initially returned **63/300 Japanese and 17/100 English** translations; 320/400 were pending. One accepted unfinished Japanese phrase was rejected by a subsequently added guard, leaving **79/400 (19.75%) translated and 321/400 (80.25%) pending** under the latest deterministic checks. All 39 earlier accepted candidates were rerun through the revised alignment parser and reverse probe; all 39 still passed. The corpus script treats all failed candidates as pending and does not separately label a rejected subset.

Passing the verifier did not imply semantic correctness. On the fixed corpus, accepted examples still include `弾がない` → `沒有彈簧` (wrong object), `胡桃のあを応援する` → `支援核桃的` (name lost), `水飲んでくる` → `水喝來了` (changed action), and `回線が重い` → `沉重的線路` (literal mistranslation). The unfinished `みんなと一緒に…、ね` → `大家一起來吧。` was an unsupported completion; the new guard now demotes it. These are observed lower bounds, not an exhaustive independent category audit. No clear number or negation mismatch was found in the accepted rows reviewed, but zero such errors has **not** been established as a release gate.

The blinded source/translation-only sheet contains 100 Japanese and 50 English Phase 9 utterances. A Codex review, **not an independent human review**, recorded 20 accepted translations (10 correct, 7 acceptable, 3 wrong) and 130 pending. All three wrong accepted rows had incoherent Japanese ASR source. Because the reviewer was Codex and the sample is from the earlier run, this does not meet the independent human acceptance gate.

The 30-minute Chrome/YouTube Japanese solo soak on 2026-09-25 used the actual Process Loopback → Faster-Whisper → translation → Sherpa diarization → SQLite pipeline. The Session completed and 193 Final originals survived in SQLite. Only **23/193 (11.9%)** had a Final translation; 170/193 (88.1%) remained without one. The latter include 53 `uncertain_source`, 12 `rejected`, 104 `pending`, and one `verifying` when finalization timed out. The bounded translation queue reached its capacity of 12. Peak app RSS was **976.9 MiB**, and mean app CPU was **64.8% of one core**. An approximate overlapping Ollama probe window measured **1,605.8 MiB peak RSS** and **300.6% of one core mean CPU**. No 7B model was loaded during this balanced-preset soak. The highest reported smoothed translation latency reached **128.8 s**, far beyond natural live use. This soak predates the retry-pacing and paged-scan fix; those fixes have tests but no second 30-minute soak yet.

Latency probes: 15 real-model Partial calls averaged **0.603 s** (median 0.391 s). The fixed 400 Final calls averaged **10.15 s** (median 11.45 s, P95 18.19 s) without live queue wait. A 150-row real-model review probe averaged **9.70 s** per Final; its alignment/reverse evidence work averaged approximately **10.0 s** for rows that reached verification. The live queue added much more delay, so offline averages must not be presented as Studio latency.

The soak exposed false Final approvals, including `どう?` → `你好？` and `んんんんん` → `囉嗦`. A subsequent targeted guard now blocks repeated filler, Japanese output with no Chinese characters, and an added inverted Spanish punctuation mark; these new guards have unit tests but were added after the 30-minute process had loaded its code. Other semantic errors remain possible because the 1.5B alignment model can approve its own wrong translation and the reverse lexical probe cannot prove full meaning preservation.

Eight recorded Japanese utterances were translated under no context, previous one, previous three, and previous 30-second context. Each mode produced two accepted outputs; longer context also supplied plausible but unsupported story details on garbled ASR source, and previous-one context changed one clothing-design utterance to an incorrect clothing-wearing action. The default was therefore reduced to no context. In a real-model prompt-injection probe, the English instruction-like source remained pending; the Japanese source was translated as literal speech rather than obeyed. This shows only those test cases, not general injection immunity.

The ASR confidence value is derived from `exp(mean(avg_logprob))`; it is a heuristic confidence proxy, not a calibrated probability of correct transcription. The full Phase 1–10 suite passed **446 tests** on 2026-10-02, and `compileall` and `git diff --check` passed. Mock tests cover alignment, numeric/negation/modality/entity guards, glossary matching, 7B repair, persistence, export, queue bounds and recovery. The real-model failures above take precedence over green unit tests for the release gate.

The current gate is therefore **NO**: false approvals remain, translation coverage is too low, and sustained live latency is too high. The blind review is an assistant review rather than independent human acceptance. Clean Windows, Installer, Overlay hardware, source matrix, GA, and Phase 11 remain outside this phase.

## Reproduction

Use `scripts/phase10_retranslate.py` for the 22, 400, or 150 fixed rows; `scripts/phase10_context_probe.py`, `scripts/phase10_injection_probe.py`, and `scripts/phase10_latency_probe.py` for real-model probes; and `scripts/phase10_live_soak.py` for the real Windows process-audio integration run. Probe outputs are local, ignored files under `data/phase10/`; no raw audio is written.
